# `ui/chat-side-panel/js/` — chat and session management modules

Split from the original monolithic `chat.js` (1637 lines) and `sessions.js` (2468 lines) into focused modules, each under ~520 lines. Everything flows one direction — no circular imports.

## Chat modules (bubble rendering, streaming, sending, UI)

| Module | Exports | Purpose |
|--------|---------|---------|
| `chat-bubble.js` | `addChatBubble`, `updateLastBubble`, `_fillAgentBubble`, `linkifyText`, `escapeHtml`, `_renderMarkdownBody`, `_formatRelativeTime`, `_refreshAllBubbleTimes`, `_parseCreatedAt` | Bubble DOM creation, markdown rendering (marked + DOMPurify), linkification, relative timestamps. Sets `app.addChatBubble`, `app._linkifyText`, `app._renderMarkdownBody` at module scope. |
| `chat-bubble-actions.js` | `_addBubbleActions`, `_getBubbleText`, `_getBubbleCopyText`, `_bubbleAnchorId`, `_resetBubbleDeleteBtn`, `_resetAllBubbleDeleteBtns`, `_handleBubbleDeleteClick`, `_deleteTurn`, `_makeBubbleDeleteBtn`, `_setDeleteIcon`, `_setActionIcon`, `_renderActionIcons`, `_setBubbleModel`, `_setBubbleModelFromMeta`, `_modelLabelFromMeta` | Per-bubble action row (footer): **per-turn model tag** (`model EFFORT`, e.g. `deepseek-v4-flash HIGH`, left-truncated so the model's end stays visible), collapse/expand, read-aloud (SpeechSynthesis), copy, and per-turn delete (two-click trash → ⚠️ → confirm, resolved server-side by walking the parent chain). The footer renders on **streaming** bubbles too — a live reply, or one being recovered from the DB by the reconcile loop, gets the row as soon as it has real text (placeholder `…` is skipped); only the destructive **delete** button is held back until the turn finalizes (the streaming class drops → `_setBubbleText` re-calls `_addBubbleActions`, which adds delete via the reuse branch). The model + reasoning-effort come from the assistant interaction's `metadata` (persisted by the loop's `_build_meta`) on history/reconcile, and from `app._activeTurnModel`/`app._activeTurnEffort` (set in `chat-activity.js` off the live `llm_call_end` event) on a fresh turn. Sets `app._addBubbleActions` at module scope. |
| `chat-stream.js` | `_stripToolCalls`, `appendStreamToActiveBubble`, `finalizeAgentResponse`, `ensureStreamingBubbleForActiveTurn`, `finalizeAgentStep`, `markAgentInterrupted`, `seedStreamingBubble`, `attachToolCallsToLastBubble`, `_setBubbleText`, `_findAgentBubbleForTurn`, `_wsTurnBuffers` | Live streaming from WebSocket: accumulates chunks per turn (`_wsTurnBuffers`), finalizes/interrupts agent steps, attaches tool-call accordion panels to agent bubbles. **Lazy tool-call bodies:** a panel built from light history data keeps its call list on the container; the first time the "N tool calls" head is opened it fetches the bodies from `/session-turn-detail` and rebuilds its rows in place (preserving which were expanded). Live calls carry their bodies already, so they never trigger a fetch. Sets all streaming `app.*` methods at module scope. |
| `chat-send.js` | `sendMessage`, `sendStopMessage`, `abortChatStream`, `applyChatGate`, `_canChat`, `_autoResizePill`, `_updateScrollIndicator`, `_updateInputRowState`, `_saveDraft`, `_clearDraft`, `_restoreDraft`, `_renderPendingBubbles`, `_startOutboxPoll`, `_outboxHasPending`, `_persistLastSessionSeq`, `_loadLastSessionSeq` | Message sending pipeline: outbox retry queue (survives refresh), draft persistence, chat gate (sign-in check), session_seq persistence, self-healing watchdog, stop/interrupt, pill textarea auto-resize + scroll indicator dot. Sets `app.abortChatStream` and `app.refreshChat` at module scope. |
| `chat-ui.js` | `initChat` | Wires everything together: sets remaining `app.*` methods (`app.updateLastBubble`, `app.autoResizeChatInput`, etc.), binds chat input/keyboard/send events, execution mode toggle, continue/stop buttons with 500ms poll, scroll-to-bottom chevron with auto-scroll lock, input area padding (ResizeObserver), mobile focus-on-first-tap, initial gate + draft restore. Also calls `initTaskFrames()`. |
| `chat-terminal-engine.js` | `initTerminalChatEngine`, `activateTerminalChat`, `deactivateTerminalChat`, `sendTerminalInput`, `focusTerminalChat` | **Terminal Chat** agents (engine `terminal_chat`): replaces the whole bubble area with a live xterm.js terminal bound to a PTY (shared registry in `app/api/terminal.py`). On session load `activateTerminalChat` POSTs `/api/v1/chat/terminal-chat/activate` to get/create the PTY id, mounts xterm, and opens the terminal WS for output (string frames are JSON control — ping is answered with pong, never painted). `term.onData`/`onResize` forward keystrokes **and mouse events** (when the program enables mouse reporting) + viewport size to the PTY over the WS — the same mechanism as the admin terminal (`ui/shared/js/terminal.js`); Shift+Tab is intercepted to CSI Z. The chat pill sends single lines over HTTP `/write` (carriage-return Enter) via `chat-send.js`. `sendTerminalInput`/`focusTerminalChat` back the on-screen keys (below). Sets `app.terminalChatKey`/`app.terminalChatFocus`/`app.show|hideTerminalKeys` consumers. |
| `chat-terminal-keys.js` | `initTerminalKeys` | On-screen **key view the pill takes on** for Terminal Chat. A keyboard toggle in the chat footer (`#chat-term-keys-btn`, hidden until Terminal Chat mounts) adds `.term-keys-open` to `#chat-input-area`; the pill (`#chat-input-row`) then hides its normal controls and the `#chat-term-keypad` grid (a child of the pill) **overlays the whole pill box** — same border/radius/background/resting height — turning the composer into a fixed **3-row × 8-col** number pad (0-9) + arrows + shortcut keys. Each chip fires a **single** keystroke straight to the PTY via `app.terminalChatKey` (no Enter appended, unlike the pill) so the user can drive TUI menus, move the cursor, pick numbered options, and interrupt (`^C`). Key→byte map mirrors the admin keybar (`ui/shared/js/files.js` → `chipBytes`). The engine calls `app.showTerminalKeys`/`hideTerminalKeys` on mount/unmount (unmount also closes the view, restoring the pill). |
| `chat-task-frames.js` | `initTaskFrames` | Draws a **border around every run of bubbles in the same "task"** (one request + the agent's work + any approval/feedback turns). **Grouping comes from the backend** `GET /admin/settings/tasks/session/{id}` (the authoritative source — it runs the keyword rule **plus a fast LLM tie-breaker** that folds on-subject follow-ups onto the current task, which a client-only rule can't do). The fetch builds a `userMsgId → task index` map; the draw assigns every bubble to a task by that map. Until the fetch lands (first paint / endpoint down) it falls back to a **local text-only rule** so a border still shows instantly. **Both paths ignore synthetic `[ORCHESTRATION EVENT]` / event/automation "user" rows** (mirror of `_is_synthetic_user` in `app/admin/tasks.py`) so a background wake-up never splits a session. The frames are a **non-reparenting overlay** — absolutely-positioned boxes appended behind the bubbles in `#chat-messages-inner` — so streaming, reconcile, per-bubble actions, and the virtual scroller are untouched. A `MutationObserver` (+ scroll/resize) redraws them; placeholders preserve height so a task's extent stays correct when virtualised. Re-pulls the grouping on session change + when a new genuine user turn appears. Sets `app.redrawTaskFrames` + `app.refreshTaskGrouping`. |

## Session modules (dropdown, lifecycle, loading, agent selection)

| Module | Exports | Purpose |
|--------|---------|---------|
| `session-list.js` | `_sessionsCache`, `populateSessionSelect`, `_renderSessionRows`, `_setTriggerLabel`, `_fetchRelatedSessions`, `applySessionTitle`, `_formatRelativeTime`, `_truncate` | Session dropdown list: fetches sessions from `/api/v1/db/sessions`, renders rows with drag handles, pin icons, status spinners (running/unread), spawn badges, relative timestamps. Manages the header label and related-sessions chips — a persistent spawn-family tab bar (a "Main" tab for the orchestrator plus one tab per spawned helper, identical whether viewing the orchestrator or any spawn, with the currently-open session highlighted), plus browser-session tabs. The family + active highlight come from `/related`'s `orchestrator`/`spawns` fields. `applySessionTitle` handles the live titler from the WebSocket. |
| `session-core.js` | `interruptSession`, `switchToSession`, `deleteSession`, `patchSession`, `togglePin`, `startRename`, `_headerRenameSession` | Session lifecycle actions: switching sessions (teardown, loading spinner, load chat, drain replayed events, send WS resume), deleting (interrupt run + DELETE API + switch to next or create fresh), pinning (PATCH), and inline rename (dropdown row + header long-press, both use the same inline-input pattern). |
| `session-agent.js` | `_agentsCache`, `_lastSessionPerAgent`, `_loadLastSessionMap`, `_saveLastSessionMap`, `findWebagentAgent`, `createWebagentAgent`, `ensureWebagentAgent`, `populateAgentSelect`, `_refreshAgentAbilities`, `_agentIconFor`, `_setAgentTriggerLabel`, `_renderAgentRows`, `_fetchAgentRunningStatuses` | Agent selection: loads agents from API, manages the agent cache (`_agentsCache`), the last-session-per-agent map (localStorage), and the webAgent singleton (find-or-create from the `default` template). `populateAgentSelect` sets `app.currentAgentId`. Abilities cache (`window.__currentAgentAbilities`) gates the "Send to agent" button. |
| `session-load.js` | `loadSessionChat`, `refreshTranscript`, `_maybeLoadMoreOnScrollTop`, `_showDebugBubble` | Core session loader: fetches messages from `/api/v1/db/session-messages`, handles `restricted` responses (token refresh + retry, auto-create fresh session), renders via windowed virtual scroll, attaches tool-call panels from persisted data, sets up **bidirectional** infinite scroll. **Fast open:** the opening fetch is small and, when a saved scroll position exists for the session, CENTRED on it (`around_id`) instead of always hauling the newest 100 — so a long session reopens right where the user left off. Older rows page in on scroll up (`before_id`); newer rows on scroll down (`after_id`, `_maybeLoadMoreOnScrollBottom`) when opened mid-history. **Light open:** every fetch is `light=1` — tool-call BODIES (arguments, results, LLM input/output) are NOT downloaded; only headings (name + duration) render, and `chat-stream.js` lazy-fetches a panel's bodies from `/session-turn-detail` the first time it's expanded. The reconcile cursor is seeded at the session's true latest seq (`max_session_seq`) so opening mid-history never backfills the tail. The ctx indicator is set from the server's whole-session `context_tokens` (the small window would under-report). Exposes `_maybeLoadMoreOnScrollTop`/`_maybeLoadMoreOnScrollBottom` for the virtual-scroll handler. While a load runs it sets `app._sessionLoadInFlight` and calls `app.abortNeighborWarm()` (cancelling any background neighbour pre-load — the on-screen session always wins); once the load settles it calls `app.warmNeighborSessions()` to warm the next/prev pinned neighbours when idle (see `session-swipe.js`). `refreshTranscript` is a **hard** reset of just the transcript area for the current session (drops the message cache, clears the bubbles, re-fetches + re-renders from the DB; never reloads the page) — wired to the header refresh button beside the agent name; differs from `app.reloadCurrentSession`, which reuses the cache. Sets `app.loadSessionChat` + `app.refreshTranscript` at module scope. |
| `session-swipe.js` | `_initPinSwipeNavigation` | Touch/pointer swipe between pinned sessions: horizontal drag slides the current transcript away and reveals the next pinned session's bubbles (preloaded from cache). Includes desktop prev/next buttons. **Background neighbour warming:** pre-loads ONLY the next + previous pinned sessions (the two the arrows/swipe can reach next) so navigation feels instant, and ONLY when idle — every warm fetch is `requestIdleCallback`-scheduled (timer fallback), runs one-at-a-time at `priority: 'low'`, is `light=1`, mirrors what a real open would download (anchored `around_id` window when that neighbour has a saved scroll position, else newest), and is skipped while a turn is running / the active session is loading / the tab is hidden. Exposes `app.warmNeighborSessions` (the active-session loader calls it once a load settles) and `app.abortNeighborWarm` (the loader calls it the instant a new load begins, so a warm can never compete with the on-screen session). |
| `session-init.js` | `registerSessionApi`, `initSessions` | Entry point: `registerSessionApi` sets `app.populateSessionSelect`, `app.populateAgentSelect`, `app.loadSessionChat`, `app.applySessionTitle`, `app.reloadCurrentSession` and wires focus persistence. `initSessions` builds the session dropdown (click, long-press rename, drag reorder, delete), the agent picker popup (+ button), header delete button, **header refresh button** (resets the transcript via `refreshTranscript`), TUI bridge status poll, session list poll, and swipe navigation. Boot sequence: `populateUserSelect` → `populateSessionSelect` → `loadSessionChat`. |

## Boot order

1. **Module evaluation** (ES import time) — all `app.*` assignments at module scope run immediately in dependency order
2. **`initChat()`** — sets remaining chat methods, wires input/send/stop/continue, execution mode, scroll chevron, gate, draft restore
3. **`registerSessionApi()`** — sets session API methods on `app`, loads saved focus positions
4. **`initSessions()`** — builds dropdown UI, agent picker, header buttons, starts polling (TUI bridge, sessions, related sessions), runs boot sequence (user-panel → sessions → load current chat)
