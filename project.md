# WebAgent Project Description

This project appears to be a web-based agent system, likely designed for automation, task execution, and possibly interaction with web UIs. It's built with Python for the backend logic and a web frontend (HTML, CSS, JS). Key features include:

## Core Components:

*   **Agent Logic (`app/agent`)**: Contains the core logic for the agent, including:
    *   `loop.py`, `streaming_loop.py`: Agent execution loops, suggesting sequential or streaming task processing.
    *   `prompts.py`: Manages prompts for the agent's language model.
    *   `error_classifier.py`: Handles error classification, indicating robust error handling.
*   **API and Backend Services (`app/api`)**: Provides API endpoints for various functionalities:
    *   `agent.py`: Agent-related API (e.g., triggering runs, status).
    *   `chat.py`: Chat interface or communication with the agent.
    *   `db_viewer.py`: For viewing database contents.
    *   `terminal.py`: Integration with a terminal, possibly for executing shell commands.
*   **Database Integration (`app/db`, `migrations`, `supabase`)**: Supports both local and remote database access.
    *   `interface.py`: Generic database interface.
    *   `local.py`: Local SQLite database handling (indicated by `local_botboss.db`, `local_webagent.db`).
    *   `supabase.py`: Integration with Supabase for cloud-based database and possibly other services.
    *   `migrations`: SQL migration scripts for database schema changes.
*   **Tool Management (`app/tools`)**: A system for defining, loading, and tracking tools the agent can use.
    *   `browser.py`: Likely includes browser automation tools.
    *   `loader.py`, `registry.py`: For loading and registering tools.
    *   `tracker.py`: Tracks tool usage or execution.
*   **Admin and Guardrails (`app/admin`)**: Components for administrative tasks and ensuring agent safety/constraints.
    *   `db_mode.py`, `settings.py`: Database mode and general settings management.
    *   `guardrails.py`: Implements safety or operational guardrails for the agent.
    *   `review.py`: Possibly for reviewing agent actions or logs.
*   **Frontend (`ui`)**:
    *   HTML (`index.html`), CSS (`app1.css`, `app2.css`, `app3.css`), JavaScript (`agentWs.js`, `chat.js`, `dbMode.js`, `main.js`, `terminal.js`, `toolLog.js`, etc.).
    *   Suggests a rich web interface for interacting with the agent, real-time updates (WebSockets: `agentWs.js`), chat functionality, and potentially a view for database interactions.
*   **Android Integration (`android`)**: Appears to have an Android wrapper or component, potentially allowing the web agent to run or be controlled from an Android device.
    *   `MainActivity.java`: Android main activity.
    *   `server.py` (under `android/app/src/main/python`): Suggests a Python server running within the Android app.

## Key Files & Directories:

*   `app/main.py`: Main entry point for the Python application.
*   `requirements.txt`, `pyproject.toml`, `uv.lock`: Dependency management for Python.
*   `start_webAgent.sh`, `start_webAgent.bat`: Scripts for starting the application on different OS.
*   `test_*.py`: Various test files (e.g., `test_config.py`, `test_env.py`, `test_openrouter.py`, `test_supabase.py`, `integration_test.py`, `final_test.py`).
*   `screenshots`: Directory for screenshots, possibly generated by the browser automation tools or for documentation.
*   `tasks`: Contains markdown files outlining sub-agent tasks, suggesting a modular approach to agent development.
*   `WEBAGENT_ENHANCEMENT_SPEC.md`: Indicating ongoing development and formal specification of features.
*   `README.md`, `SETUP_GUIDE.md`, `MIGRATION_INSTRUCTIONS.md`, `FUTURE_PLANS.md`: Documentation and project guides.

## Overall Purpose:

The project aims to provide a comprehensive framework for developing and deploying intelligent web agents, spanning from core agent logic and tool orchestration to robust backend APIs, database integrations, and a user-friendly web interface, with potential for mobile deployment. The emphasis on error handling, guardrails, and structured tasks suggests a system built for reliability and extensibility.
